# 论文方向人才地图

输入一个论文方向关键词，实时联网检索全网论文，把该方向的研究者和他们的合作关系画成一张可交互的**学术结构图**；检索结果也可切换到 **HR 可用的学术短名单**（表格 + 筛选 + CSV 导出）。

不依赖任何预设名单——每次检索都是现场从 dblp 全库拉数据构建的。可公开试用（内建限流与 OpenAlex 降级提示）。

dblp 目前前置了 [Anubis](https://github.com/TecharoHQ/anubis) PoW 反爬；本项目会在普通 HTTP 客户端里自动完成挑战并复用 cookie。若出口 IP 仍被硬拦，会自动降级到 OpenAlex（需配额/API key）或 Crossref，并在界面标明数据源。

## P0 能力

1. **快速检索（默认）**：关键词 → 可探索合作网络（Louvain 聚类、发文/引用切换节点大小、机构高亮）。深度模式为可选，**默认关闭**。
2. **深度模式（可选）**：以方向核心学者为种子滚雪球扩展连通性；非该方向的引入者标注为「经关联引入的合作者」，与「方向核心」区分。
3. **学者详情卡**：点击节点打开侧边详情（非直接跳转 Scholar）。含姓名、角色、方向发文、引用、论文署名机构（发表当时）、主题、代表作样本、dblp id、数据缺口标记、可复制字段，以及 Google Scholar **作者搜索页**链接（非精确主页）。
4. **机构文案**：统一为「论文署名机构（发表当时）」，不暗示现职。
5. **关键词放宽提示**：空结果或 AND 过严时，给出可点选建议（只保留首词 / 去掉末词等），点选后重搜。预置 chip 仍可用。
6. **限流 / 降级可读**：同 IP 并发限流有明确错误文案（已有结果时留在结果页）；OpenAlex 配额用尽或补充失败时，主图仍可用，stats 显示「补充已降级」，详情卡与短名单标注缺口。**所有提示条统一放在范围条下方的提示区**（文档流里，不是浮层）：数据源回退/补充降级、深度进行中/深度失败、限流、深度阶段连接中断各占一行，多条按这个顺序堆叠，结构图和短名单相应下移，任何组合都不会压住短名单工具栏（导出 CSV、筛选开关）、结构图的标签页和查找框。长期残留的提示（降级、深度失败、限流、连接中断）带关闭按钮，关掉只是隐藏，新检索会重新显示。
7. **短名单视图**：结构图旁「结构图 | 短名单」切换。表格字段：姓名、论文署名机构（发表当时）、方向发文、方向相关引用（缺失留空）、角色、团体/聚类 ID、Scholar 搜索 URL、缺口标记。筛选含最少发文、仅方向核心、是否有机构、聚类、姓名关键字。CSV 导出可直接被 `pandas.read_csv` / Excel 读取：UTF-8（带 BOM）、逗号分隔、CRLF 换行，**第一行即表头**，没有注释行或尾部说明；字段按 RFC 4180 加引号（含逗号、双引号、换行的字段整体加双引号，内部双引号写成两个）。列依次为：姓名、论文署名机构（发表当时）、方向发文数、方向相关引用（缺失留空，不填 0；真实被引 0 次写 0）、角色标签、团体/聚类ID、Scholar搜索URL、数据置信/缺口标记、时间范围、查询词、导出时间、免责声明——后四列每行重复；导出时间为浏览器本地时间的 ISO 8601（如 `2026-10-01T13:25:00+08:00`），不含逗号。**防公式注入**：文本列（姓名、论文署名机构、角色标签、Scholar搜索URL、数据置信/缺口标记、时间范围、查询词、导出时间、免责声明）中以 `=` `+` `-` `@` 制表符或回车开头的单元格，前面加单引号 `'`，表格软件按文本显示、不执行；数字列（方向发文数、方向相关引用、团体/聚类ID）不转义。（命令行版只生成静态 HTML，不导出 CSV。）
8. **时间范围筛选**：全部 / 近 5 年 / 近 3 年。口径：按论文发表年份、以当前年份为基准、含当年（2026 年时近 5 年 = 2022–2026，近 3 年 = 2024–2026）；年份缺失或标为未来年份的论文只计入「全部」。结构图、短名单、CSV 的发文数、方向核心判定（最少发文阈值）、合作边、聚类、引用/机构聚合与排序都只用范围内论文；引用 = 范围内论文至今的累计被引。界面顶部条幅、统计栏、短名单表头、详情卡与 CSV（「时间范围」列 + 免责声明列中的口径说明 + 文件名）都注明当前范围。某个范围没有结果时，提示里会给出有结果的更宽档位（「切到近 5 年」「切到全部」，附人数），点击后下拉框同步切换、直接用已抓取的数据恢复结果；报错提示里也保留「返回上次结果」入口（结构图 / 短名单 / 导出仍可用）。过滤作用在**已抓取的论文**上：切换范围复用已抓取的 dblp 论文与 OpenAlex 补充，只在本地重新建图，不重新请求。
9. **引用 0 与缺失分开**：按「该学者在当前范围内参与引用统计的论文」中有几篇取到引用数据（OpenAlex 按 DOI 命中且记录带 cited_by_count，或备用源记录自带被引数字段——Crossref 为 is-referenced-by-count；字段缺失/为 null/非数字都算没取到，只有字段存在且为 0 才是真实 0；数值须为 0–10⁹ 的整数：整数值的有限浮点数可用（5.0 记 5），inf/NaN（JSON 的 1e400、Infinity、NaN）、5.5、超上限、非 ASCII 数字（如「²」「٥」）、超过 12 位的数字串一律按缺失，解析不会让检索失败，见 test_citations.py）分三种：全部取到 → 显示总和，真实 0 就显示 0；部分取到 → 显示已取到部分之和并标「≥」（下限），注明 x/y 篇；一篇都没取到（缺 DOI / 未命中 / 补充降级 / 备用源没给被引数）→ 显示「未补全」，不当作 0。界面悬浮提示、详情卡、短名单、复制摘要一致；CSV 中缺失留空、部分缺失写下限（下限为 0 时留空，避免被误读成真实 0），原因写在「数据置信/缺口标记」列（如「缺引用」「引用部分缺失(x/y篇有数据)，数值为下限」）；同发文数时缺失排在有值的后面。

## 不做（当前范围外）

外联触达、现职担保、LinkedIn/ATS、精确 Scholar 主页、CRM、多租户；以及 P1：机构关键词筛选增强、隐藏非方向合作者滤镜增强、代表作/DOI 深挖、图-表双向高亮、检索参数分享、预置词表深度对齐等。

## 安装与本地运行

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python3 app.py
```

浏览器打开 http://127.0.0.1:8000

可选：

```bash
export OPENALEX_MAILTO="your@email.com"   # OpenAlex polite pool / Crossref mailto
export OPENALEX_API_KEY="..."             # 2026 起建议配置免费 key，避免匿名 IP 日预算耗尽
export CONTACT_URL="https://example.com"  # 公开部署时建议设置，写入 User-Agent
```

### 公开部署

SSE 长连接 + 深度模式可能跑几分钟，适合常驻容器（Hugging Face Spaces / Render / Fly.io 等），不适合 Vercel 类 serverless。

```bash
docker build -t talent-map .
docker run -p 7860:7860 -e OPENALEX_MAILTO="you@example.com" talent-map
```

部署到 Hugging Face Spaces：SDK 选 Docker，关联本仓库；Settings 中可设 `OPENALEX_MAILTO`、`CONTACT_URL`。

公开部署保护机制：

| 机制 | 做什么 | 为什么 |
|---|---|---|
| 全局 dblp 节流 | 同一时刻整个进程只有一个 dblp 请求在飞 | 避免多访客叠加违反 Crawl-delay |
| 单访客并发限制 | 同一 IP 有检索在跑时拒绝新请求 | 防止单人占满全局队列 |
| 参数上限收紧 | `papers`≤2000，`seeds`≤15 | 避免单次占队过久（命令行版不受限） |
| OpenAlex 配额降级 | 用完或失败时主图仍返回，界面明示降级 | 不静默丢数据、不误导成「没有引用」 |
| Anubis PoW | 自动完成 dblp 软挑战并缓存成功 JSON 页 | 恢复被反爬拦截的检索 API |
| 备用论文源 | dblp 失败时依次试 OpenAlex、Crossref | 出口 IP 硬拦时仍能出图 |

进程内缓存（30 分钟 TTL，dblp 响应 20 分钟）仅单实例有效，**请单副本部署**。每份缓存都有容量上限，超出按 LRU 淘汰、写入时顺带清理过期项；上限可用环境变量覆盖，超出允许范围会被封顶到边界，非整数回落默认值：

| 缓存 | 默认上限 | 允许范围 | 环境变量 |
|---|---|---|---|
| 检索结果（关键词+参数+时间范围） | 64 | 1–1024 | `TALENT_MAP_RESULT_CACHE_MAX` |
| 原始论文 + OpenAlex 补充（切换时间范围复用，单条可达数 MB） | 16 | 1–64 | `TALENT_MAP_RAW_CACHE_MAX` |
| 深度模式结果 | 32 | 1–512 | `TALENT_MAP_DEEP_CACHE_MAX` |
| dblp 响应（检索翻页 + 深度模式作者检索） | 128 | 1–1024 | `TALENT_MAP_DBLP_CACHE_MAX` |

缓存测试：`python test_cache.py`（不联网）。

## 关键词怎么写

**只用 1~2 个核心词。** dblp 多个关键词之间是 AND：

| 查询 | 命中论文（量级示意） |
|---|---|
| `BEV` | 很多 |
| `BEV perception` | 适中 |
| `BEV perception autonomous driving` | 很少 |

结果过少或报错时，页面会给出可点选的放宽建议。

## 深度模式

直接按方向建图往往碎片化（组与组之间无共同作者）。深度模式以该方向发文最多的学者为种子，拉入其合作者，连通性是构造出来的。

代价：会混入不做该方向的人 → 界面区分「方向核心」与「经关联引入的合作者」。耗时约每位种子 14 秒；网页版先出快速结果，再后台替换。

## 数据来源

- **dblp**（`dblp.org/search/publ/api`）：论文、作者身份、合作关系
- **OpenAlex**（`api.openalex.org`）：被引、署名机构、主题（按 DOI 批量匹配，规避同名）

## 数据覆盖与机构含义

补充数据并非人人都有。界面会标注覆盖率与缺口（缺引用 / 缺署名机构等）。

**论文署名机构（发表当时）** 来自论文元数据，反映发表当时的署名单位，**不等于现职担保**。列表里没出现的机构，不代表该人没有单位，只代表这批元数据里没有或补充降级。

Google Scholar 入口是**作者搜索页**（可带姓名与署名机构缩小范围），不是精确个人主页；同名需人工甄别。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 论文数 | 300 | Web 上限 2000；dblp 分页硬上限 10000 |
| 最少发文 | 2 | 方向核心入图门槛 |
| 深度模式 | 关 | 可选；种子数默认 10（Web 上限 15） |

## 已知限制

- dblp 单方向最多约 10000 篇，超大方向会截断
- dblp 间歇 HTTP 500（已退避重试）；Crawl-delay ~4s，速度有硬下限
- OpenAlex 每日配额有限（公开试用全站共享）；耗尽后引用/机构补充降级，主图仍可用
- 机构为发表当时署名，非现职；Scholar 为搜索页非精确主页
- 深度模式引入的合作者不一定做该检索方向
- 短名单「方向相关引用」缺失时留空（不填 0），勿当作零引用
